| D522 | 2026-10-23 | **How sound plays (owner's answers, Block D; the 600 KB row is D523).** (1) **Web Audio only:** the files are fetched and decoded; **no `<audio>` elements**, no new runtime dependency (the two runtime dependencies stay `preact` and `@preact/signals`). (2) **One format:** mono MP3 at about 48 kbps, one small file per sound, **no loops.** Claude Code converts the owner's picks while authoring and commits the result (generators run at authoring time, technical design §12.3); if its container has no audio converter it says so and the owner gets a task (a new npm dev dependency would need the owner's yes). (3) **iPhone needs a tap.** The tap on the Settings switch creates and resumes the audio and loads the sounds. If Sound is already On at app start, the audio context is created suspended and the files are fetched and decoded at once, so the first tap anywhere only has to resume it; resuming is done on `click` or `touchend`, not on `pointerdown` or `touchstart` (recent iOS does not count those as a gesture for audio). The iOS `interrupted` state after a call is treated as paused. A sound due before unlock, or while audio is paused, is **skipped and never queued or replayed.** After a call, a lock or returning from another app, the next tap resumes audio. (4) **Sounds are precached like all other assets** (offline play); Claude Code checks that the build's cache patterns include `.mp3`, and an offline test fetches one. **"Nothing is loaded with Sound Off" means the page itself fetches and decodes nothing;** the service worker still precaches the files at install (they count in the 600 KB). (5) **Failure is silence:** a file that fails to load or decode plays nothing and shows nothing. (6) **Debug (readings (e) of D520):** a **Play sound** row in the debug panel plays each of the seven; it works only while Sound is On; it is a **UI-only action** that writes nothing, does not touch the save and does not set `debugUsed` (a second recorded exception to technical design §15, after "Set last export age"). (7) The test hook that swaps in a recording fake engine is a documented global read by the sound module; it does nothing unless a test sets it. **The fake replaces only the audio output;** every readiness rule (Sound On, unlocked, running, page visible) still runs, and tests can set the fake context's state (running, suspended, interrupted) and the page's visibility. (8) **The one place cues come from:** the UI watches what the game already shows. If a cue cannot be worked out without changing `src/core/`, **stop and ask** (no core change is authorised). (9) **Found in the red-team pass (a reading for the owner at D528):** a result is sounded **only the first time it appears.** Reopening a result sheet, replaying a fight or Delve from a log, or replaying from the Library plays nothing; and a playback that is skipped or closed early plays at most the one sound for its result. (10) **Same-moment window:** 150 ms hold, strongest plays (owner, 2026-10-23); tests use a fake clock. | Owner, Block D; details by Claude | Proposed |
| D523 | 2026-10-23 | **Size: the 600 KB row stays (owner's answer, Block D4 (a)).** (1) **The unit is 1 KB = 1,024 bytes**, the project's own measure (D494: v1.0 = 506 KB = 518,460 bytes). v1.1 measured **582,081 bytes (568 KB, 306 files)**, so the row's 614,400 bytes leave **32,319 bytes (about 31.6 KB)**. (2) **All sound files together: hard cap 30 KB, target about 24 KB (about 3.8 s in total).** MP3 does not shrink under gzip, so file size counts in full. (3) **The whole build is the binding limit.** The new code (sound module, manifest rows, Settings row) also counts, and Claude's rough estimate is 3–6 KB gzipped (an estimate, not a measurement). So the real room for sound is what is left after the code is built: **sound budget = 614,400 − (build without sounds) − 1,024 bytes of margin, and never more than 30 KB.** Claude Code measures the build without sounds before converting the picks (task SF.6) and reports the number. (4) If the picked sounds do not fit, **the build stops and asks the owner:** the answer is fewer or shorter sounds, **never a silent change to the row.** (5) The row will probably need a new measured value in a later milestone (v1.3 or v1.4: music, new art); that is a decision for then. | Owner, Block D4 (a); numbers from progress.md and D494 | Proposed |
